# Amplify Todo

This is a deployment-ready React Todo app for StackSim's supported Amplify
Gen 2 Data workflow. The repository already includes:

- the Todo backend in `amplify/`;
- the pinned Amplify CLI and backend packages;
- local StackSim deployment settings; and
- npm scripts for deploying, watching, and deleting the sandbox.

You do not need to create backend files, install Amplify packages separately,
or export AWS environment variables.

## Supported configuration

This example intentionally uses the StackSim Amplify configuration covered by
the test suite: one model with scalar fields, public API-key authorization, and
the pinned `@aws-amplify/backend-cli@1.9.0` CLI.

The package identity is also pinned to `stacksim-amplify-gen2-data-fixture` so
Amplify generates the resource names currently supported by StackSim. Changing
the `name` field in `package.json` changes those generated names and is not yet
supported.

CRUD, list/filter/pagination, and create/update/delete subscriptions are
supported. Amplify Auth, Storage, user Functions, relationships, indexes,
custom operations, Hosting, and `pipeline-deploy` are outside this example's
current scope.

## Quick start

The commands use two terminals and two directories:

```text
<StackSim repository root>/
├── package.json                      Terminal 1: StackSim
└── examples/amplify-todo/
    └── package.json                  Terminal 2: backend and React app
```

### 1. Start StackSim — Terminal 1

Run these commands from the **StackSim repository root**, which contains the
top-level `package.json`, `src`, and `examples` directories:

```bash
npm install
npm run build
npm run start:amplify
```

`start:amplify` starts StackSim with the local AppSync TLS listener required by
the generated Amplify client. Leave this terminal running.

If StackSim is already running from an ordinary `npm start`, stop it with
**Ctrl+C** and restart it with `npm run start:amplify`.

StackSim is available at:

- API endpoint: [http://127.0.0.1:4566](http://127.0.0.1:4566)
- Console: [http://127.0.0.1:4566/_stacksim/console](http://127.0.0.1:4566/_stacksim/console)

### 2. Trust the local CA — macOS, one time

The AppSync HTTP and realtime endpoints use a loopback-only development
certificate. Trust its CA before opening the Todo app:

1. Download the CA from
   [http://127.0.0.1:4566/_stacksim/appsync/ca.pem](http://127.0.0.1:4566/_stacksim/appsync/ca.pem),
   or use `.stacksim/data/cloudformation/custom-resource-pki/ca.pem` from the
   StackSim repository root.
2. Open **Keychain Access** and select the **System** keychain.
3. Choose **File > Import Items** and import the CA file.
4. Double-click **stacksim CloudFormation development CA**, expand **Trust**,
   and set **When using this certificate** to **Always Trust**.
5. Close the certificate window and authenticate when macOS prompts.
6. If your browser is already running, fully quit and reopen it.

This is StackSim machine setup, not Todo application setup. Repeat it only if
you remove the certificate from Keychain Access or delete/regenerate the
`.stacksim` data directory. Trust only the CA generated by your local StackSim
checkout, and remove it from Keychain Access when you no longer use the local
example.

### 3. Deploy and run the app — Terminal 2

From the **StackSim repository root**, run:

```bash
cd examples/amplify-todo
npm install
npm run deploy
npm start
```

`npm run deploy` deploys the checked-in backend to StackSim and generates
`amplify_outputs.json`. After it completes, `npm start` launches the React app.

Open [http://127.0.0.1:5173](http://127.0.0.1:5173). You can now create,
complete, delete, and filter Todos, with realtime updates delivered through
AppSync subscriptions.

## Commands

Run these commands from `examples/amplify-todo`:

| Command | Purpose |
|---|---|
| `npm start` | Start the React development server |
| `npm run deploy` | Deploy the `amx01` sandbox once and refresh `amplify_outputs.json` |
| `npm run backend:watch` | Watch `amplify/` and redeploy supported backend changes |
| `npm run backend:delete` | Interactively delete the `amx01` sandbox and its Todo data |
| `npm run build` | Build the React app into `dist/` |
| `npm run preview` | Preview the production frontend build |

The generic wrapper is also available for less common Amplify commands:

```bash
npm run ampx -- sandbox --once --identifier amx02 --outputs-out-dir .amplify/amx02
```

## What gets deployed

The checked-in backend is defined by:

- `amplify/backend.ts`
- `amplify/data/resource.ts`

It creates a `Todo` model with these fields:

| Field | Type | Required |
|---|---|---|
| `title` | String | Yes |
| `description` | String | No |
| `priority` | Integer | No |
| `completed` | Boolean | No |
| `dueAt` | DateTime | No |

The deployment creates the AppSync, DynamoDB, IAM, Lambda, Step Functions,
S3, SSM, Logs, and nested CloudFormation resources generated by Amplify Gen 2.
The generated `amplify_outputs.json` connects the React client to those local
resources and is intentionally ignored by Git.

## Local deployment settings

The `scripts/ampx-local.mjs` wrapper supplies these defaults to the unmodified
Amplify CLI:

```text
AWS_ACCESS_KEY_ID=admin
AWS_SECRET_ACCESS_KEY=password
AWS_REGION=eu-west-1
AWS_DEFAULT_REGION=eu-west-1
AWS_ENDPOINT_URL=http://127.0.0.1:4566
AWS_EC2_METADATA_DISABLED=true
CDK_DEFAULT_ACCOUNT=000000000000
CDK_DEFAULT_REGION=eu-west-1
AMPLIFY_DISABLE_TELEMETRY=1
```

The wrapper deliberately overrides matching shell variables so an existing AWS
profile or endpoint cannot redirect this local example to an AWS account. It
only configures the CLI child process; it does not change your shell, patch
Amplify, or replace any generated output.

## Update or remove the backend

To redeploy after editing `amplify/data/resource.ts`:

```bash
npm run deploy
```

For continuous backend updates:

```bash
npm run backend:watch
```

Stop watch mode with **Ctrl+C**. Supported changes preserve the Todo table and
records when replacement is not required.

To delete the sandbox:

```bash
npm run backend:delete
```

Review the confirmation prompt carefully. Deletion removes the sandbox and its
Todo records while preserving StackSim's shared managed bootstrap and unrelated
sandboxes.

## Build the frontend

```bash
npm run build
npm run preview
```

When `amplify_outputs.json` exists, the build copies it unchanged into `dist/`.
The output contains a public API key suitable only for this local example. Do
not use this authorization model for private or production data.

This builds the frontend locally; it does not deploy Amplify Hosting.

## Inspect the deployed resources

Open the [StackSim console](http://127.0.0.1:4566/_stacksim/console) and sign in
with access key `admin` and secret key `password`.

Start in **CloudFormation** and open the stack printed by `npm run deploy`. Its
outputs identify the AppSync API and key, while its nested stacks link to the
generated DynamoDB, IAM, Lambda, Step Functions, S3, SSM, and Logs resources.
The Todo records are visible in the generated DynamoDB table.

## Local TLS certificate

Complete Quick Start step 2 before launching the app. Clicking the AppSync
endpoint does not establish certificate trust on macOS. The UI deliberately
keeps network guidance generic and directs you back to this README. Do not
disable TLS verification globally.

## Troubleshooting

### Deployment fails with `NoStack: CloudFormationStack object does not hold a stack`

Confirm the `name` in this example's `package.json` is exactly
`stacksim-amplify-gen2-data-fixture`, run `npm install`, and deploy again. The
current StackSim Amplify slice supports the generated resource names associated
with that pinned package identity. Amplify's `NoStack` message hides the
underlying CloudFormation validation failure when the identity is changed.

### The UI says “Deploy the Amplify sandbox”

- Confirm `npm run deploy` completed successfully.
- Confirm `amplify_outputs.json` exists in `examples/amplify-todo`.
- Reload the page without cache.
- Restart `npm start` if the output was generated while Vite was stopped.

### The CLI tries to use AWS instead of StackSim

Use `npm run deploy`, not `npx ampx` directly. The npm script supplies the
local endpoint and credentials to the Amplify CLI child process.

### GraphQL or subscriptions report a network error

Rebuild and restart StackSim after pulling server changes, then confirm it was
started with `npm run start:amplify`. Use the link shown in the UI error banner
to approve the loopback development certificate, and approve it only when the
host is `127.0.0.1` or `localhost`. Verify that `amplify_outputs.json` points to
the current StackSim process; redeploy if its AppSync port changed.

### Requests return unauthorized

Do not edit `amplify_outputs.json`. Confirm its `data.api_key` is present and
that `amplify/data/resource.ts` still uses `allow.publicApiKey()` with API key
as the default authorization mode.
