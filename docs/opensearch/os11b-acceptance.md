# OS-11B embedded cross-cluster search

> Scope revision, 2026-11-17: this is a historical implementation/evidence record. The [developer simulator contract](implementation-plan.md) supersedes its earlier full-phase, AWS-parity and exhaustive-fault completion requirements. Existing behavior is retained; unsupported breadth is not a mandatory backlog.

Seven managed connection operations and their seven legacy facades now execute real cross-cluster searches over resource-owned embedded indexes. This branch does not complete the network, replication or migration phase.

A source owner creates a DIRECT outbound connection. The destination account and Region expose its inbound view and alone can approve or reject it. Approval durably enables routing; deleting either view revokes it. Domain generations are pinned, so replacing a domain cannot inherit a connection. Domain deletion requires removing nonterminal incoming and outgoing connections first. Both domains must be active, use the same supported OpenSearch version, and enable fine-grained security and node-to-node encryption. Accounts and Regions within one installation and AWS partition can connect. No external cluster or VPC endpoint is synthesized.

Creation returns PENDING_ACCEPTANCE; acceptance returns ACTIVE after commit. Rejection and deletion commit REJECTED/DELETED immediately. These are actual local transitions, without simulated provisioning delays. Deleted/rejected records are visible for 15 days, with at most 1000 retained records per installation and 20 nonterminal incoming/outgoing connections per domain. List APIs support the documented connection/domain filters with exact values, 1–100 results and account/Region/direction/filter/snapshot-bound HMAC tokens that expire after ten minutes. Mutation failures restore the previous catalog; searches cannot observe a connection during publication.

GET/POST `/<local-index>,<alias>:<remote-index>/_search` uses the existing embedded query interpreter over one combined authorized read view. Sorting, pagination, aggregations, post-filtering, source projection and exact k-NN selection apply globally. Remote hit names include the alias. Source and destination IAM/domain policies are checked for the current signed caller. The destination must explicitly grant `es:ESCrossClusterGet` on its bare domain ARN; `domain/name/*` does not match. FGAC resolves each side's actual indexes and requires search plus `indices:admin/shards/search_shards`. Document and field restrictions apply before documents leave their owner engine or enter predicates/aggregations. Remote-only requests do not require local index permissions. Current role mappings and policies are rechecked on every request.

The coordinator permits 100 selectors, 100 resolved indexes, 50,000 scanned documents and 64 MiB of source/schema data across all domains, with a 30-second maximum deadline and any shorter body timeout. Existing 10 MiB request, 32 MiB response and 16 active requests per participating domain limits remain. Sources are read synchronously inside StackSim; no documents are copied to destination indexes and no interprocess transport is claimed. Gateway requests use the existing HTTPS/SigV4 path. Successful remote owner reads feed existing request metrics/logging/audit. `SkipUnavailable=ENABLED` skips an unavailable destination and reports `_clusters.skipped`; authorization, missing indexes, missing/revoked connections and malformed requests fail rather than silently dropping data.

The explicit profile requires IAM credentials and literal connection aliases. Internal-user propagation, wildcard cluster selectors, remote writes, SQL/PPL, msearch/count, PIT/scroll, search pipelines/hybrid, dictionary packages, external clusters, VPC networking, replication and migration remain unsupported. Existing local-only search behavior is unchanged. Service software upgrades and wider phase dependencies remain separately inventoried.

Focused evidence:

- `test/opensearch-connections.test.ts`: official modern/legacy SDKs and signed OpenSearch TLS client; lifecycle/restart/revocation, global sort/sum/terms/k-NN, FGAC/DLS/FLS/shard discovery, policy boundaries, unavailable destination, HMAC pages, validation, failed publication rollback and cross-account/cross-Region owner approval.
- `test/opensearch-connection-recovery.test.ts`: forced termination after creation commit, before approval commit, after approval commit and after deletion commit; recovered routing honors only committed decisions and preserves source documents.
- `test/browser/opensearch-connections.spec.ts`: create, destination approval, actual combined aggregation and revocation at desktop and mobile widths.
- Existing hybrid, FGAC, protocol, query and legacy tests cover the shared paths changed by this branch. These are focused runs, not a full regression run; Linux/Windows and native/AWS reference execution are not established.

Primary contracts: [managed cross-cluster search](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/cross-cluster-search.html), [connection configuration API and filters](https://github.com/awsdocs/amazon-opensearch-service-developer-guide/blob/master/doc_source/configuration-api.md), [service IAM actions](https://docs.aws.amazon.com/service-authorization/latest/reference/list_es.html), and the pinned models in this directory.

## Domain metadata comparison

`CompareDomainConfiguration` reads seven supported categories directly from both domain engines: aliases, templates, ingest pipelines, ISM policies, security roles, security role mappings and internal users. Calls require `es:CompareDomainConfiguration` on both same-account domain ARNs, with each domain's resource tags and Region in its authorization context. The request goes to the source Region. Connections or replication are not prerequisites. Comparison does not mutate either domain.

Object key order and ISM update timestamps do not cause differences; array order remains significant. Alias comparisons include actual index bindings and write-index settings. Password verifier differences report `Policy=redacted` without either value. Independently salted verifiers can differ even for the same password, so this does not establish password equivalence. Internal master credentials are not part of the user-resource metadata catalog and are never exposed.

The read budget is 64 MiB of underlying metadata across both domains/categories, one million visited fields and 30 seconds. Each category includes at most 1000 names per difference type, 100 fields per diverged item, 10 KiB per displayed value and 1 MiB of field/name detail. Response omissions set `Truncated=true`; item counts remain complete. Unknown or unimplemented categories reject explicitly. Cross-account metadata comparison, alerting monitors, cluster settings, component templates and custom security action groups remain outside this profile.

`test/opensearch-comparison.test.ts` exercises actual current metadata through the official SDK, independent IAM grants on both domains, verifier redaction, deterministic paths and truncated detail with complete counts. The existing desktop/mobile Connections journeys also compare actual ingest-pipeline differences. The console exposes category selection, count summaries and field details.

The remaining managed DR API has an additional compatibility prerequisite: the current AWS service requires OpenSearch 3.7 or later, while this embedded profile currently selects 2.19. No successful replication peer, failover or switchover is claimed from configuration-only state. [Comparison contract](https://docs.aws.amazon.com/opensearch-service/latest/APIReference/API_CompareDomainConfiguration.html), [managed DR requirements](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/disaster-recovery.html).
