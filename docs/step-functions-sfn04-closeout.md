# SFN-04 closeout — CloudFormation, CDK and deployment lifecycle

Date: 2026-09-25. Status: **complete — focused acceptance passed**.
Requirements: **SFN-P1-005** and deployment composition of **SFN-P1-012**.

The earlier inspection was revalidated: StateMachine already shared the expanded
SFN-03 ASL validator; S3 definitions and the Activity provider were missing.
This phase extends that implementation. There is no CloudFormation interpreter,
alternate execution catalog, new Step Functions public action or widened task
integration registry.

## Requirement and evidence map

Provider and lifecycle suites validate malformed/unsupported shapes and disabled service/provider configuration parity. |

| Substitutions before strict validation | Scalar substitutions, multiple-key concatenation, missing substitutions, malformed resulting JSON, and the effective 1 MiB limit use the shared ASL validator/compiler/registry. | Authorized immutable S3 assets | Owning S3 reads use stack-role identity/resource-policy evaluation and requested versions. Manifests record bucket/key/version/ETag/size/SHA-256 and accepted UTF-8 source; operation asset artifacts preserve it for restart. `-assets` covers version pinning, unversioned changes between review and execution (including the second admission read), missing objects/versions, encoding/BOM/size/JSON/YAML boundaries, wrong Region, version/object-tag policy conditions, identity/resource-policy deny and no StateMachine mutation. Existing `cloudformation-assets`, `cloudformation-template-url-authorization`, recursive-admission and change-set regressions remain green. |
| Updates and accepted content | Provider consumes the materialized effective definition; rollback resources retain accepted source plus substitutions. No provider makes an ad hoc S3 read. Existing executions keep their definition/role snapshot. A later S3 write alone never changes deployment/execution; a newly requested same-key unversioned update compares accepted digests. The asset suite tests direct and change-set redeployment, no-op, and rollback with the source deleted. |

| Atomic failed updates | StateMachine validates the entire proposed definition, role and configuration before mutation. Asset/lifecycle suites prove denied or malformed updates preserve current effective definition and revision behavior. |
| Create/stabilization/update/no-op/replacement | StateMachine callbacks reconcile create, definition/role update, untag, tag and pre-delete phases; Activity reconciles create/untag/tag/pre-delete. Activity suite restarts each Activity callback. All recover through bounded physical ID/generation/phase checkpoints rather than execution state. |
| Retention, running execution and recreation | SDK and CDK tests finish admitted executions after deletion, retain selected workflow/role resources, clean them up and deploy again. ## Learning commands and limits

Start StackSim with `npm run dev`, then follow the example guide. The runner uses
the ordinary pinned CDK CLI, supported endpoint settings and an outbound network
tripwire; it does not rewrite synthesized templates.

```text
node examples/cdk-step-functions-lifecycle/run.mjs deploy v1
node examples/cdk-step-functions-lifecycle/run.mjs execute
node examples/cdk-step-functions-lifecycle/run.mjs inspect
node examples/cdk-step-functions-lifecycle/run.mjs deploy v2
node examples/cdk-step-functions-lifecycle/run.mjs fail
node examples/cdk-step-functions-lifecycle/run.mjs execute
node examples/cdk-step-functions-lifecycle/run.mjs destroy
node examples/cdk-step-functions-lifecycle/run.mjs cleanup
```

S3 definitions are same-account/same-Region UTF-8 JSON, not YAML or compressed
content. Activity Name remains required by the CloudFormation schema. General
resource import/drift, Express, JSONata, enabled execution logging, X-Ray, KMS,
versions, aliases, redrive and Distributed Map remain explicit boundaries.
Retained resources keep their ownership tags and must be cleaned up before a new
stack can own the same names. Historical executions remain available under the
existing retention contract. Ambiguous legacy Activity bindings are not silently
attached to a recreated resource; already issued worker tokens remain usable.
